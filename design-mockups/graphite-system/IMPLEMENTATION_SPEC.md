# FloatAsk「朝日／近月」实施与验收规范

版本：1.5.0  
更新：2026-11-03  
适用范围：答案窗、紧凑答案窗、框选层、悬浮工具栏、更多菜单、历史与收藏、全部设置页、首次配置、更新界面及 Windows 可访问性。

## 1. 唯一规范源与变更纪律

后续设计或代码实现按以下优先级读取：

1. `design-tokens.yaml`：颜色、圆角、尺寸、字体、动效和对比度的机器可读唯一来源。
2. `IMPLEMENTATION_SPEC.md`：组件结构、行为、禁止事项和验收规则。
3. `floatask-graphite-system.kanva.pptd`：页面与状态的可视验收基准。
4. `../README.md`：设计资产索引和决策记录。
5. `light/`、`dark/` 早期样张：仅用于风格溯源，不得作为实现依据。

任何设计变化必须在同一轮同步更新 token、实施规范、相关样张和索引。不得只在代码中新增颜色、圆角、阴影或主题分支。若实现受 Electron／Windows 限制，先记录差异，再决定调整规范或实现，不得静默偏离。

## 2. 产品气质与主题命名

- 产品气质：安静、清晰、克制、可靠的 Windows 桌面工具；服务长时间阅读，不追求装饰性“科技感”。
- 白天主题显示名：**朝日 · 白天**；深夜主题显示名：**近月 · 深夜**；自动模式：**跟随系统**。
- 名称取自《近月少女的礼仪》的日月意象。功能标签“白天／深夜”必须保留，不能只显示彩蛋名称。
- 朝日使用柔和暖白，近月使用中性暗色。双主题共享品牌签名“取景框角”。

朝日／近月禁止：琥珀色终端风、网格背景、扫描线、发光边框、霓虹渐变、无功能意义的装饰标签。前哨 · 工业的装饰以第 16 节登记表为准。

## 3. 双主题不变量

- 所有主题共用布局、尺寸、间距、图标、字体层级和组件状态；朝日／近月共用圆角，前哨通过 shape token 覆盖圆角并使用 bevel 切角。
- 主题切换只替换语义颜色、描边和投影，不重新排版，不通过简单反色生成朝日。
- 组件只引用 `surface`、`surface2`、`text`、`body`、`muted`、`accent` 等角色，不散落硬编码色值。
- 朝日大面积表面禁止纯白；不使用黄色滤层或大面积绿色表达“护眼”。
- 主操作统一引用 `primaryButton` 与 `onPrimary`；朝日主按钮使用灰雾蓝 `#506B92` 与浅色前景，禁止另用近黑或纯黑按钮。
- 朝日的选中态使用同色系浅蓝 `accentSoft`，开关与选中图标使用 `accent`，次操作使用暖灰 `surface3`；三层色彩不得互换或另建色板。
- 设计示范中的来源截图与当前主题一致。真实历史缩略图仍按原始截图显示，但必须标注来源应用，不能用另一主题界面冒充截图内容。
- 浮层依靠 1 px 描边与柔和投影分离，不能使用发光。

## 4. 圆角与轮廓

只允许以下圆角等级：

| 对象 | 圆角 |
| --- | ---: |
| 外窗、大型浮层 | 16 px |
| 容器、composer、菜单 | 12 px |
| 输入框、按钮、provider 卡片、菜单项 | 10 px |
| chips、Logo 底、键帽 | 8 px |
| Switch、骨架条、完整悬浮工具栏 | 全圆角 |

- 共边嵌套遵循 `R内 = R外 − 间距`。设置窗外窗 16 px，侧栏内缩 1 px，因此侧栏为 15 px。
- 悬浮工具栏高 52 px、内边距 5 px、外半径 26 px；品牌区与主按钮均为 42 px 高、半径 21 px。
- 收起态外半径 22 px，32 × 32 px 品牌标识内缩 6 px、半径 16 px；不得再回退为 R8 方形底。
- 取景框角保持直角，不套圆角。
- 不使用覆盖矩形修补轮廓，不在同一层级混用近似圆角。

## 5. 边框、表面与投影

- 所有浮层使用 1 px `floating` 描边；普通容器与控件使用 1 px `control` 描边；激活与键盘焦点使用 `active`。
- 分隔线使用 `divider`，不能用另一套临时灰色。
- chips 可以只用表面色；主发送按钮不增加额外描边。
- 朝日使用暖白表面与深色半透明描边；近月使用暗色表面与浅色半透明描边。
- 同层卡片不通过多重阴影制造层级；优先使用表面差、分隔线与留白。

## 6. 字体与阅读

- Latin 使用 Liter，中文使用 MiSans；代码始终使用等宽字体。
- 正文字号提供 12／14／16 px，默认 14 px。标准阅读行高 1.55，长文可使用 1.5。
- 阅读密度只改变行距与段落节奏，不改变控件尺寸、圆角或窗口宽度。
- 自定义字体只影响界面与阅读，不影响代码字体和 OCR。
- 不用缩小字号解决内容溢出；长内容进入回答视口滚动。
- 辅助文字必须保持至少 4.5:1 对比度；朝日主表面 token 的实测值记录在 `design-tokens.yaml`。

## 7. 答案窗与内容行为

- 标题栏、上下文和输入区固定，只有回答视口滚动。
- 紧凑答案窗默认 480 × 360 px，只呈现摘要；完整回答进入扩展阅读。
- 紧凑态保留重新框选、置顶、展开和关闭，不得为了简洁删除功能。
- 代码块和必要时的表格在容器内部横向滚动，外窗宽度不变。
- 流式生成仅当用户位于底部时自动跟随；向上阅读后暂停并显示“回到底部”。
- 未实际使用联网资料时不得生成来源标注；无网降级不得复用旧引用。
- OCR 在本机完成，但 OCR 文字会随模型请求发送；视觉模型接收压缩截图，文案不得混淆两者。

## 8. 设置、历史与隐私

- 设置导航顺序固定：模型服务、联网检索、通用与快捷键、历史与隐私、外观与阅读、更新与关于。
- 选中导航使用 `accentSoft` 与 `accent`，不新增左侧高亮条或第二种选中样式。
- 设置页主按钮统一为“保存更改”；连接测试、连接结果和错误反馈就地显示。
- 历史列表与详情并列；列表星标和详情收藏状态必须同步。
- 重新打开历史只恢复本机上下文，不自动重新发送模型请求。
- 清除历史先显示影响范围，再就地二次确认；同时提供取消与确认，不使用整窗红色。
- 危险色只用于需要立即处理的错误和危险操作，不作装饰。

## 9. 悬浮工具栏与更多菜单

- 一级功能固定：浮问字标拖动、框选（Alt+Q）、剪贴板解释、历史、更多。
- 工具栏品牌区使用独立“浮”字标；只有框选按钮使用取景框图标，禁止品牌区与框选按钮重形。
- 展开尺寸 328 × 52 px；左右半胶囊 44 × 52 px；上下横置半胶囊 64 × 44 px。
- 距边缘 24 px 内松手吸附；展开时距边缘 8 px。
- 吸附采用锚点模型：吸附时记住锚点（边 + 半胶囊位置），展开从锚点推算，收起直接回到同一锚点、贴边落位；四边展开后与屏幕边间距统一为 8 DIP。
- 从吸附态（收起或展开）拖动时保持原吸附边；吸附边随配置 `bubbleDock` 保存，重启后恢复为对应半胶囊；外接屏移除时按新工作区重新吸附锚点。
- 悬停 120 ms 或点击展开；移开 300 ms 后收起；拖动或菜单打开时禁止收起。
- 更多菜单只放设置、隐藏工具栏、退出浮问；一级已有功能不得重复。
- 菜单 224 × 152 px，容器 R12、菜单项 R10、行高 36 px，与工具栏间距 12 px。
- 菜单根据屏幕边缘朝可用空间展开；Esc／点击外部关闭，焦点返回更多按钮。
- 隐藏工具栏后可从系统托盘恢复。

## 10. 动效与系统行为

- 主题颜色过渡 120 ms；跟随系统监听 Windows 深浅色变化，无需重启。
- 工具栏收放宽度均为 180 ms ease-out；收起前 80 ms 淡出次级内容，展开时次级内容延迟 60 ms 淡入。
- “浮”字标保持 14 px 并连续移动；品牌点击区随胶囊在 40 × 42 px 与 32 × 32 px 间收放，不让整栏同时淡入淡出。
- 用户启用“减少动态效果”时，主题和工具栏直接切换最终状态。
- 所有动画不得改变点击区域的位置语义，不得导致输入区跳动。

## 11. 首次配置、更新与关于

- 首次配置固定为模型服务、快捷键与隐私、开始使用三步；上一步、关闭和稍后配置都不得清空已填内容，再次进入从未完成步骤继续。
- Ollama 可不要求 API Key；其他服务的密钥使用 DPAPI 加密，不出现在日志、诊断信息或明文配置中。测试失败保留全部输入。
- 首次配置明确本机 OCR 与可选截图上传的区别；完成页只保留一个主要动作“开始第一次框选”，完整设置作为次入口。
- 更新依次呈现版本信息、下载进度、SHA-256 校验和用户确认安装；校验通过前“重启并安装”保持 disabled，不得自动重启或覆盖模型配置与本机历史。
- 更新失败必须区分检查／下载、校验和安装阶段，说明安装包是否保留及当前版本是否可用。校验失败删除安装包并阻止安装；安装失败保留当前可用版本。
- 关于页集中提供版本、检查更新、GitHub、发布说明、MIT 与第三方许可；外部链接使用系统默认浏览器打开。
- 诊断信息由用户主动复制，复制前可预览；仅包含版本、系统版本、DPI、显示配置和脱敏错误码，不得包含 API Key、OCR 原文、截图或完整对话。

## 12. Windows、状态与可访问性

- 默认、hover、选中、disabled、loading、streaming、empty、error 使用同一组件结构。
- 键盘焦点使用 2 DIP `active` 外描边、2 DIP 偏移，不被父容器裁剪；不能只靠颜色微弱变化表达。disabled 不进入 Tab 顺序。
- 图标按钮提供可访问名称与 tooltip；图标风格、尺寸和点击区域保持一致。
- 菜单打开后焦点进入菜单，方向键移动、Enter 执行；Esc 先关闭菜单并返回触发按钮，再次 Esc 才关闭答案窗。
- 错误提示说明发生了什么、数据是否已发送、如何恢复；不武断归因第三方应用。
- Windows 布局与命中区域统一使用 DIP，并以每屏工作区为边界，不覆盖任务栏；吸附阈值为 24 DIP，展开后距屏幕边缘 8 DIP。
- 外接屏移除时，窗口迁回主屏工作区；跨屏后重新读取目标显示器 DPI，不在已有缩放上重复缩放。
- 480 × 360 DIP 的紧凑答案窗在 100%／125%／150% 缩放下分别对应 480 × 360、600 × 450、720 × 540 物理像素，布局与字号保持 DIP 语义一致。
- Windows 高对比度使用系统色板，优先于朝日／近月；文字、边界和焦点均使用系统语义色，不做简单反色，也不以主题色覆盖系统焦点。跨主题设计板展示该状态时，必须在预览上方标注“系统接管配色 · 非朝日／近月主题色”。
- 减少动态只移除非必要运动，直接切换最终状态，不移除完成、错误或状态变化等功能反馈。
- 屏幕阅读器不逐字播报流式内容，只播报回答完成、错误与恢复动作；用户主动移动焦点时仍可读取当前内容。

## 14. 登记常量与派生（1.4.3）

- microText 字号（kicker 7.5 / micro 8.5 / caption 9.5）仅用于全大写装饰性 kicker、微型注记与辅助标签；正文与控件文字不小于 auxiliaryMin 10。
- radius 增补 media 9 / compact 7 / mini 5：media 用于浮层媒体（灯箱图片）；compact 用于 23–31 px 高的紧凑文字按钮、分段控件与输入框；mini 用于消息行内小动作；其余圆角继续沿用 window/container/control/small/pill；图标按钮（30 px 方形命中区）沿用 control 10。
- 新增语义描边 border-danger（近月 #E1A0A84D／朝日 #A14D584D），仅用于破坏性悬停与错误提示边框；选中态描边统一用 border-active，不再使用旧青蓝／玫红硬编码。
- 答案窗标题栏与卡片同面（transparent + 分隔线），双主题一致；窗口外圈不留任何主题色底板。
- 组件几何唯一来源：答案窗 compact/expanded 尺寸、工具栏展开/收起尺寸与半径（含收起外半径 22、主半径 21）、阅读密度系数（compact 0.92／relaxed 1.12）登记于 token 源；主进程经 src/main/design-constants.js 读取，渲染进程使用生成的 --fa-* 变量；window-geometry.js 保持 vm 纯函数，其字面量由单测对账守卫。
- 答案窗卡片表面统一为 surface（设计稿 page-1/9/25 整卡同面、divider 分隔）；bg 仅作更底层底色，不用于卡片面。

## 15. 上游演进与新功能扩展

- 五十页是当前设计基线，不是功能白名单或页数上限；上游新增功能必须识别、保留并接入同一语义系统，不得以 UI 迁移为由回退。
- 开始实现前记录当前分支、上游 ref、未提交工作、重叠文件和新增功能。重叠文件按功能合并，禁止用 reset、clean 或整文件覆盖消除冲突；生成的 CSS 在 token 源解决冲突后重新生成。
- 新功能先复用现有 token 与组件，再考虑受控 variant；只有全新信息结构或交互原语才新增设计，并同步 token、规范、样张和验收矩阵。
- provider、来源、quick chips、历史筛选、设置项与菜单项采用数据驱动、稳定 ID 和 i18n，不依赖固定数量或 `nth-child`。数量增长使用滚动、换行或溢出，不缩小字号硬塞。
- 入口开放但层级稳定：新设置进入有序导航，新内容进入回答视口，新工具动作默认进入更多或溢出菜单；胶囊一级动作与窗口主操作不得无限增长。
- 新配置提供默认值与非法值回退；新 IPC 增量添加并保留既有调用；未知状态提供可恢复 fallback。已有 token 改名或删除前保留别名并记录弃用。
- 用额外 provider、来源和设置项的扩展 fixture 验证几何、键盘顺序和双主题，不为未知功能提前建设插件平台。

## 16. 第三主题：前哨 · 工业（1.5.0）

- 显示名 **前哨 · 工业**，主题 ID `industrial`；token 登记于 `design-tokens.yaml` 1.5.0 的 `themes.industrial`。完整设计规范见 `../../docs/superpowers/specs/2026-11-03-qianshao-industrial-theme-design.md`，视觉基准为 `../industrial/qianshao-mockup.html`。
- 色板、形状、装饰登记表、微标签数据来源与黄色预算以设计规范第 3 节（3.1–3.6）为准，本节不另抄色值。要点：讯号黄 `#FFE400` 为强调与主操作；每个窗口最多两块实心黄（品牌块 + 主操作），胶囊工具栏的实心黄只给「框选」。
- 形状：主题级 `shape` token 提供 `cornerShape`（朝日／近月 `round`，前哨 `bevel`，生成 `--fa-corner-shape`）与半径覆盖（window 16、container 10、control 7、small 5、media 6、compact 5、mini 3，pill 保持 999）。切角使用 CSS `corner-shape: bevel`，不使用 clip-path；描边与投影沿斜边绘制。
- 装饰：`ornaments` token 提供网格线色与尺寸、斜纹色。装饰只出现在登记表列出的位置，表外装饰一律不加；携带信息的微标签只显示真实数据，取不到时显示占位（如 `lat --`），不得编造。
- 装饰层 `src/renderer/ornaments.css` 的全部规则以 `[data-theme="industrial"]` 为作用域，只引用 token、不改组件结构；朝日／近月下零影响。
- 跟随系统仍只在朝日／近月之间切换；前哨只能手动选择，选中后原生主题按深色处理。
- Windows 高对比度照旧由系统色板接管；斜纹、网格、角标在 forced-colors 下隐藏。减少动态时传送带静止、过渡即时。

### 16.2 新功能接入主题清单

- 新界面只使用 `--fa-*` token：组件 CSS（`src/renderer/*.css`，`theme.css` 除外）不得写死颜色或圆角，由 `tests/css-tokens.test.js` 与 `tests/radius-tokens.test.js` 强制（`data:` URI 内的图形与只读 alpha 的 mask 渐变除外）。
- 组件不得按主题 ID 分支：JS 中不判断 `data-theme`、不写 `=== 'industrial'`；需要知道“是否为显式主题”或原生明暗时，使用共享注册表 `src/shared/theme-ids.js`（渲染进程为 `window.FloatAskThemeIds`）。
- 仅属于前哨的装饰一律写在 `src/renderer/ornaments.css`，以 `[data-theme="industrial"]` 为作用域，并先登记到设计规范 §3.4 装饰登记表；表外装饰不加。
- 阅读区排版（正文、OCR 原文、输入内容的字体、字号与行高）与主题无关，新功能不得按主题改动。
- 新增一整套主题 = `design-tokens.yaml` 的 `themeIds` 与 `themes` 块 + `src/shared/theme-ids.js` 条目（含原生 `scheme`）+ i18n 显示名键 + 设置“外观与阅读”中的主题卡片。前两项不同步时 `tests/theme-ids.test.js` 失败；生成器按 `themes` 逐块输出，运行 `npm run build:tokens` 后 `--check` 通过即可。
