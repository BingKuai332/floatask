# 前哨 · 工业：第三主题设计规范

日期：2026-11-03
状态：设计稿已获认可，待评审本规范
视觉基准：`design-mockups/industrial/qianshao-mockup.html`（v0.1，7 块设计板）

## 1. 目标

在「朝日 · 白天」「近月 · 深夜」之外新增一个深色主题「前哨 · 工业」，取《明日方舟：终末地》集成工业系统的设计语言（炭黑 + 讯号黄、切角、角标、警示斜纹、计数读数、设备状态、传送带），做出明确的工业感；正文的字体、字号与行高保持与近月一致，不因装饰牺牲阅读。

不使用终末地的名称、Logo、字体、图标和截图素材，只借通用工业设计语汇；界面字串里不出现 `aic` 等游戏术语。

## 2. 已定决策

| 项 | 决定 |
| --- | --- |
| 装饰强度 | 设计稿 C 档原样：网格可铺在回答区下方，黄色可用于回答标题、项目符号、chips 与输入框描边，标题栏与上下文行使用等宽微标签 |
| 主题 ID | `industrial`（配置与代码使用，显示名以后可改而 ID 不变） |
| 显示名 | 中文「前哨 · 工业」，界面短名「前哨」，提示「深色 · 切角」；英文 `Outpost`，提示 `Dark · beveled` |
| 跟随系统 | 保持现状：白天用朝日，深夜用近月；前哨只能手动选择 |
| 设计流程 | HTML 视觉稿先行；实现完成后用实机截图为设计板补页 |

对比度由设计稿第 07 板按 WCAG 公式实算，全部 ≥ 4.5:1（green 作为非文字状态色 ≥ 3:1）。

### 3.2 形状

- 新增主题级 token `cornerShape`：朝日 / 近月为 `round`，前哨为 `bevel`，生成 `--fa-corner-shape`。
- 前哨覆盖半径刻度（px）：window 16、container 10、control 7、small 5、media 6、compact 5、mini 3；pill 保持 999。
- 切角位置：窗口与大块容器切右上、左下两角（`border-radius: 0 R 0 R`），另两角放黄色角标；控件同规则。
- 全圆角元素在 bevel 下自动变形：胶囊工具栏成为两端尖头的六边形，滑杆圆点成为菱形。开关改为方形轨道 + 方块滑块。
- 实现依据：Electron 45.1.0 内核为 Chromium 156，已实测支持 `corner-shape: bevel` 及按角设置；描边与投影沿斜边绘制，不使用 clip-path。

### 3.3 字体

不新增字体。正文与界面沿用 Liter + MiSans；微标签、计数、时间、哈希、快捷键使用已有代码字体栈（`--fa-font-code`），在前哨下以 `--fa-font-label` 别名引用。

### 3.4 装饰登记表

每个装饰只能出现在登记的位置；表外装饰一律不加。

| 装饰 | 表示什么 | 位置 |
| --- | --- | --- |
| 黄色角标 | 品牌签名（延续取景框角）、选中 | 窗口两个直角、选中的主题卡、框选取景框（3px） |
| 黄黑警示斜纹 | 框架签名；不可撤销操作 | 标题栏左缘 7px；历史清除确认、错误卡、更新失败卡左缘 8px |
| 网格底纹 | 框架签名 | 标题栏、回答视口、设置侧栏、框选遮罩（24px）；14px 网格、线色 `#FFFFFF14` |
| 状态灯 | 6px 方块：黄 = 生成中，绿 = 完成，红 = 出错 | 答案窗标题栏 |
| 传送带条 | 正在流式生成或下载 | 标题栏下 3px、更新下载进度；完成即消失 |
| 微标签 | 真实数据，格式固定 | 见 3.5 |
| 序号 | 结构顺序 | 回答标题前 `01 //`；设置导航 01–06 与分区 05.1；来源 `[01]` |
| 键帽 | 快捷键 | 输入提示、工具栏提示、框选提示 |
| 等高线 | 框架签名 / 勘测意象；答案窗生成中加速 | 两处，线条均由 `scripts/generate-contours.js` 程序化生成（种子噪声 + marching squares），原创，非地图描摹；muted 细线 + 每 4 级一条黄色计曲线，只做 transform 漂移，减少动态时静止、高对比度下隐藏。① 答案窗：视口右下（survey 预设 `contours*.svg`），向左上淡出，不在文字之下形成高对比，漂移 60s / 90s，生成中 24s / 36s。② 设置窗：整窗一片连续山脉（ranges 预设，低频拉长的 ridged multifractal，`contours-ranges*.svg`），铺满 `.card` 底层，标题栏 / 侧栏 / 内容区共用，不再各自带网格或面板底色（标题栏只留左缘警示条，侧栏只留右侧 1px 分隔线）；细线 0.13、计曲线 0.18，径向遮罩让内容列中央更淡、四周与底部更密；漂移 120s / 160s，无加速态 |

### 3.5 微标签的数据来源

| 标签 | 含义 | 来源 |
| --- | --- | --- |
| `fa.term // node-07` | 当前会话第几轮 | 渲染进程已有的消息列表 |
| `0x3F2A` | 会话短哈希，历史列表同步显示 | 会话 ID 取 4 位十六进制摘要 |
| `src: chrome.exe` | 来源进程 | 已有前台窗口上下文 |
| `ocr 350 ch` | 识别字数 | 已有 OCR 结果 |
| `lat 0.82s` | 首字响应耗时；取不到时显示 `lat --` | 新增：主进程记录请求发出到首个 token 的时间，随流式事件下发 |
| `fa.term // settings`、`fa.term // history · 27 条` | 窗口标识与记录数 | 静态字串 + 已有计数 |

### 3.6 黄色预算与可读性底线

1. 每个窗口最多两块实心黄：品牌块 + 主操作。开关、勾选、滑块、星标、状态灯属于小控件标记，不计入。胶囊工具栏的实心黄只给「框选」，「浮」字标为暗底黄字。
2. 回答正文、OCR 原文、输入内容的字体、字号（12 / 14 / 16）、行高与近月一致；网格只能是 8% 以内的细线。
3. 动效只表达状态：传送带只在生成和下载时移动；系统「减少动态」开启时传送带静止、过渡即时。
4. 携带信息的标签不小于 10 px。
5. Windows 高对比度照旧由系统色板接管：前哨加入 forced-colors 选择器；斜纹、网格、角标在该模式下隐藏。

## 4. 架构

### 4.1 token 与生成器

- `design-tokens.yaml` 升到 1.5.0：`themeIds` 增加 `industrial`；`themes.industrial` 含 colors / borders / shadows，以及新的可选 `shape`（cornerShape + radius 覆盖）与 `ornaments`（网格线色与尺寸、斜纹色）。
- `scripts/build-theme.js`：为每个主题输出 `--fa-corner-shape` 与其 `shape` 覆盖；`:root` 默认 `round`；forced-colors 块加入 `[data-theme="industrial"]`；基础层统一给有圆角的元素加 `corner-shape: var(--fa-corner-shape)`。
- 规范修订：`IMPLEMENTATION_SPEC.md` 第 2、3 节的禁止项与「双主题共享几何」改为只约束朝日 / 近月；新增第三主题章节，引用本规范的装饰登记表。版本记录与 README 索引同步。

### 4.2 装饰层

新增 `src/renderer/ornaments.css`，在 7 个页面中紧随 `theme.css` 引入。所有规则以 `[data-theme="industrial"]` 为作用域，只用 token，不改组件结构；朝日 / 近月下零影响。

### 4.3 运行时

- `store.js` 主题白名单加入 `industrial`。
- `main.js`：`broadcastTheme()` 在前哨下把 `nativeTheme.themeSource` 设为 `dark`，下发 `theme: 'industrial'`；预览白名单同步。
- `theme.js`：`resolveTheme` 接受 `industrial`；`system` 行为不变。
- 设置页：主题卡改为四张一行（窄窗口两行），新增前哨卡与预览；i18n 增加 `theme.industrial` / `theme.industrialHint`（中英）。
- 答案窗与历史：渲染 3.5 中的微标签；主进程补首字耗时。

### 4.4 前置清理

约 30 处写死的圆角值（大多在 `settings.css`）改为 token；有意为之的 50% 圆点与 0 逐个确认是否在前哨下变为菱形或方块。

## 5. 附带修复：胶囊工具栏吸附与收放

用真实的 `window-geometry.js` 重放 `setBubbleMode()` 的几何（脚本模拟，未在实机操作），确认以下问题；现有单测是按错误值写的，因此全部通过。

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 半胶囊吸附在右边靠下、或底边靠右时，展开再收回会跳到别处（实测右边 y 900 → 686，底边 x 1700 → 1574） | 收回位置从展开后的窗口左上角重新推算；向上或向左展开时，左上角已不在原吸附点 | 吸附时记住锚点（边 + 半胶囊位置），展开从锚点算，收回直接回到锚点 |
| 2 | 右边与底边展开后离屏幕边 18px，左边与顶边是 8px | `expansionPlacement` 右 / 下分支漏加 10px 透明边距 | 右 / 下分支补上边距，四边统一为 8px |
| 3 | 收起动画开头跳一下（底边向左收起时偏 20px） | `collapseStartBounds` 用写死的 348 / 276 / 284 反推起点，284 按错误尺寸算出（应为 264） | 收起起点直接取收起前窗口的真实边界，删掉反推与魔法数 |
| 4 | 展开尺寸写死 328 / 348 / 72 | 未引用 token 常量 | 改为从 `CAPSULE_EXPANDED` 与边距推导 |
| 5 | 重启后工具栏不再吸附（据代码推断，待实机确认） | 只保存窗口坐标，不保存吸附边；启动时不执行吸附判定 | 保存吸附边，启动时恢复为对应半胶囊 |

改动范围：`src/main/window-geometry.js`、`src/main/main.js` 的工具栏状态部分，并修正 `tests/window-geometry.test.js` 中按错误值写的断言，补回归测试：四边各做三次展开 / 收回循环，锚点不变，间距为 8px。这些文件目前有未提交改动，需先提交或确认后再修。

- 系统状态：高对比度下装饰隐藏、系统色接管；减少动态下传送带静止。
- 回归：朝日 / 近月的生成 CSS 与截图不变。
